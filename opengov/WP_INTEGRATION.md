# WordPress Integration — OpenGov Funding Cards

This document explains how to add per-item funding-summary cards to the
WordPress agenda output generated by `json-to-wordpress.js`.

---

## Architecture overview

```
SOE agenda PDF / URL
      │
      ▼
agenda-scraper/json-scraper.js          ← produces meeting_*.json with financialDetails
      │
      ▼
opengov/reconcile.py                    ← Phase 4: extracts account codes, resolves CoA
      │  writes  opengov/data/reports/<meetingId>-<date>-funding-manifest.json
      ▼
opengov/card.py  --format wp            ← Phase 5.1: renders WP block markup snippet
      │  writes  e.g. /tmp/<meetingId>-card.wp.html
      ▼
json-to-wordpress.js  (modified)        ← inserts card block into each agenda item
      │
      ▼
agendas/agenda_<date>.wp.html           ← final WordPress agenda post content
```

## Step 1 — Generate the funding manifest

Run `reconcile.py` **after** `json-scraper.js` and **before** building the
WP output. Point it at the meeting JSON produced by the scraper:

```bash
cd /path/to/meetings
source opengov/.venv/bin/activate

python3 -m opengov.reconcile \
  agenda-scraper/data/meeting_<ID>_<date>.json \
  --out-dir opengov/data/reports/
```

This writes:

```
opengov/data/reports/<meetingId>-<date>-funding-manifest.json
```

## Step 2 — Generate the WP card snippet

```bash
python3 -m opengov.card \
  opengov/data/reports/2564-2026-01-08-funding-manifest.json \
  --format wp \
  --out /tmp/2564-card.wp.html
```

The snippet is a `<!-- wp:group {"className":"og-funding-summary"} -->` block
containing three nested tables (meeting totals, by-fund, and line items).

## Step 3 — Insert the card into `json-to-wordpress.js`

The card should appear **after the supporting-documents block** and **before
`processedItems.push(...)`** in the `agendaItems.forEach` loop
(around **line 691** in the current file).

### Change summary

1. **Load the manifest** at the top of the function that processes a meeting:

```js
// Near the top of generateSingleMeetingMarkup() or wherever meetings are loaded
const manifestPath = path.join(
  __dirname,
  "../opengov/data/reports",
  `${meeting.meetingId}-${meeting.formattedDate}-funding-manifest.json`,
);
let fundingManifest = null;
if (fs.existsSync(manifestPath)) {
  fundingManifest = JSON.parse(fs.readFileSync(manifestPath, "utf8"));
}
```

2. **Build a lookup map** keyed by `agendaItemId`:

```js
// Build map: agendaItemId → funding item
const fundingByItemId = {};
if (fundingManifest) {
  for (const fi of fundingManifest.items) {
    if (fi.agendaItemId) fundingByItemId[fi.agendaItemId] = fi;
  }
}
```

3. **Insert the card** after the supporting-docs block (after line ~690):

```js
// Funding card — insert after supporting-docs block
const fi = fundingByItemId[item.agendaItemId];
if (fi && fi.details.some((d) => d.accountCode)) {
  cleanedText += "\n\n" + renderFundingCard(fi);
}
```

4. **Add the `renderFundingCard` helper** (standalone JS function):

```js
/**
 * Render a WP block funding-summary card for one agenda item.
 * @param {object} fi - A single item from a funding manifest
 * @returns {string} WordPress block markup
 */
function renderFundingCard(fi) {
  const fmt = (v) =>
    v == null
      ? "—"
      : `$${Math.abs(v).toLocaleString("en-US", { minimumFractionDigits: 2 })}`;
  const typeLabel = {
    expenditure: "Expenditure",
    expenditure_decrease: "Decrease",
    revenue: "Revenue",
  };
  const t = fi.totals;

  let rows = "";
  for (const d of fi.details) {
    if (!d.accountCode) continue;
    const e = d.enriched || {};
    const label = [
      e.fund && `Fund: ${e.fund.code} ${e.fund.name}`,
      e.department && `Dept: ${e.department.code} ${e.department.name}`,
      e.object && `Obj: ${e.object.code} ${e.object.name}`,
    ]
      .filter(Boolean)
      .join(" / ");
    rows += `<tr><td>${d.accountCode}</td><td>${label}</td><td>${d.amount || "—"}</td><td>${typeLabel[d.type] || "Other"}</td><td>${d.fiscalYear || "—"}</td></tr>`;
  }

  return `<!-- wp:group {"className":"og-funding-summary","metadata":{"name":"Funding Summary"}} -->
<div class="wp-block-group og-funding-summary">
<!-- wp:heading {"level":5} -->
<h5 class="wp-block-heading">Funding</h5>
<!-- /wp:heading -->
<!-- wp:table -->
<figure class="wp-block-table"><table>
<thead><tr><th>Expenditures</th><th>Decreases</th><th>Revenues</th><th>Net</th></tr></thead>
<tbody><tr><td>${fmt(t.expenditures)}</td><td>${fmt(t.decreases)}</td><td>${fmt(t.revenues)}</td><td>${fmt(t.net)}</td></tr></tbody>
</table></figure>
<!-- /wp:table -->
${
  rows
    ? `<!-- wp:table --><figure class="wp-block-table"><table>
<thead><tr><th>Account Code</th><th>CoA Labels</th><th>Amount</th><th>Type</th><th>FY</th></tr></thead>
<tbody>${rows}</tbody></table></figure><!-- /wp:table -->`
    : ""
}
</div>
<!-- /wp:group -->`;
}
```

### Exact insertion point

In `json-to-wordpress.js`, find the block that closes the
`agenda-supporting-docs` group (ends with `<!-- /wp:group -->`). The funding
card goes **immediately after** that closing tag, still inside the item loop:

```js
// --- existing supporting-docs block ends here ---
cleanedText += `
</ul>
<!-- /wp:list -->
</div>
<!-- /wp:group -->`; // ← supporting-docs closes here

// ▼▼▼ INSERT HERE ▼▼▼
const fi = fundingByItemId[item.agendaItemId];
if (fi && fi.details.some((d) => d.accountCode)) {
  cleanedText += "\n\n" + renderFundingCard(fi);
}

processedItems.push({ itemNumber, cleanedText, hasStrongTag }); // ← already exists
```

## Pipeline script

A complete pipeline shell script that chains all steps:

```bash
#!/usr/bin/env bash
# Usage: ./scripts/build-wp-agenda.sh 2564 2026-01-08
set -euo pipefail
MEETING_ID="$1"
MEETING_DATE="$2"    # YYYY-MM-DD used in file name
ROOT="$(cd "$(dirname "$0")/.." && pwd)"

source "$ROOT/opengov/.venv/bin/activate"

# Step 1: Reconcile financial details
python3 -m opengov.reconcile \
  "$ROOT/agenda-scraper/data/meeting_${MEETING_ID}_${MEETING_DATE}.json" \
  --out-dir "$ROOT/opengov/data/reports/"

# Step 2: Build WP agenda (after manifest exists)
node "$ROOT/agenda-scraper/json-to-wordpress.js" "$MEETING_ID" "$MEETING_DATE"
```

## Alternative: post-process with Python (no JS changes needed)

If modifying `json-to-wordpress.js` is not desired, `card.py` can patch an
already-generated `.wp.html` file. This is not yet implemented but the
approach is:

1. Parse the `<!-- wp:list-item -->` blocks
2. For each block, match it to an agenda item by `agendaItemId` anchor
3. Append the `renderFundingCard` WP block inside the list item before
   `<!-- /wp:list-item -->`
